# 数据存储位置说明

## 概述

本文档说明 Supabase 和 Docker 数据库的数据实际存储位置，以及如何备份和迁移数据。

## 数据存储位置

### 本地 Docker 环境（使用 docker-compose）

所有数据存储在 `mxmdata/data/` 目录下，通过 Docker volumes 挂载：

```
mxmdata/
└── data/                          # 数据存储目录（已加入 .gitignore）
    ├── postgres/                  # PostgreSQL 数据库数据
    │   └── (PostgreSQL 数据文件)
    ├── minio/                     # MinIO 对象存储数据
    │   └── (MinIO 存储的文件)
    ├── redis/                     # Redis 数据
    │   └── (Redis AOF/RDB 文件)
    └── kong/                      # Kong 配置
        └── kong.yml
```

#### 具体路径映射

| 服务 | 容器内路径 | 宿主机路径 | 说明 |
|------|-----------|-----------|------|
| **PostgreSQL** | `/var/lib/postgresql/data` | `./data/postgres` | 数据库文件、WAL 日志等 |
| **MinIO** | `/data` | `./data/minio` | 对象存储的所有文件 |
| **Redis** | `/data` | `./data/redis` | AOF 持久化文件 |

**完整路径示例**（macOS）：
```
/Users/mxm_pro/Desktop/codes/mobile/mxmdata/data/postgres/    # PostgreSQL 数据
/Users/mxm_pro/Desktop/codes/mobile/mxmdata/data/minio/      # MinIO 数据
/Users/mxm_pro/Desktop/codes/mobile/mxmdata/data/redis/       # Redis 数据
```

### Supabase 云服务

如果使用 Supabase 云服务（`https://your-project.supabase.co`），数据存储在 Supabase 的云服务器上：

- **数据库**：存储在 Supabase 托管的 PostgreSQL 实例中
- **存储**：使用 Supabase Storage（基于 S3）或你自己的 MinIO
- **位置**：无法直接访问文件系统，只能通过 API 访问

**注意**：Supabase 云服务的数据备份和恢复需要通过 Supabase Dashboard 或 API 进行。

## 查看数据存储位置

```bash
cd mxmdata

```

### 方式二：查看实际目录

```bash

```

## 数据备份

### 备份 PostgreSQL 数据

#### 方式一：使用 pg_dump（推荐）

```bash
# 通过 Docker 容器备份
docker exec mxmai-postgres pg_dump -U postgres postgres > backup_$(date +%Y%m%d_%H%M%S).sql

# 或备份到压缩文件
docker exec mxmai-postgres pg_dump -U postgres postgres | gzip > backup_$(date +%Y%m%d_%H%M%S).sql.gz
```

#### 方式二：备份整个数据目录

```bash
cd mxmdata
tar -czf postgres_backup_$(date +%Y%m%d_%H%M%S).tar.gz data/postgres/
```

**注意**：备份数据目录时，需要先停止 PostgreSQL 容器，否则可能损坏数据。

```bash
# 停止服务
docker compose stop postgres

# 备份
tar -czf postgres_backup_$(date +%Y%m%d_%H%M%S).tar.gz data/postgres/

# 启动服务
docker compose start postgres
```

### 备份 MinIO 数据

```bash
cd mxmdata
tar -czf minio_backup_$(date +%Y%m%d_%H%M%S).tar.gz data/minio/
```

### 备份 Redis 数据

```bash
cd mxmdata
tar -czf redis_backup_$(date +%Y%m%d_%H%M%S).tar.gz data/redis/
```

### 完整备份脚本

创建 `mxmdata/backup-all.sh`：

```bash
#!/bin/bash

BACKUP_DIR="./backups"
DATE=$(date +%Y%m%d_%H%M%S)

mkdir -p "$BACKUP_DIR"

echo "🔄 开始备份..."

# 备份 PostgreSQL（使用 pg_dump，无需停止服务）
echo "📦 备份 PostgreSQL..."
docker exec mxmai-postgres pg_dump -U postgres postgres | gzip > "$BACKUP_DIR/postgres_$DATE.sql.gz"

# 备份 MinIO
echo "📦 备份 MinIO..."
tar -czf "$BACKUP_DIR/minio_$DATE.tar.gz" data/minio/

# 备份 Redis
echo "📦 备份 Redis..."
tar -czf "$BACKUP_DIR/redis_$DATE.tar.gz" data/redis/

echo "✅ 备份完成！"
echo "📁 备份位置: $BACKUP_DIR"
ls -lh "$BACKUP_DIR"
```

## 数据恢复

### 恢复 PostgreSQL 数据

#### 方式一：从 SQL 备份恢复

```bash
# 恢复 SQL 备份
gunzip -c backup_20231231_120000.sql.gz | docker exec -i mxmai-postgres psql -U postgres postgres

# 或直接恢复 SQL 文件
docker exec -i mxmai-postgres psql -U postgres postgres < backup.sql
```

#### 方式二：从数据目录恢复

```bash
# 停止服务
docker compose stop postgres

# 删除旧数据（⚠️ 会丢失所有数据）
rm -rf data/postgres/*

# 恢复备份
tar -xzf postgres_backup_20231231_120000.tar.gz -C data/

# 启动服务
docker compose start postgres
```

### 恢复 MinIO 数据

```bash
# 停止服务
docker compose stop minio

# 删除旧数据
rm -rf data/minio/*

# 恢复备份
tar -xzf minio_backup_20231231_120000.tar.gz -C data/

# 启动服务
docker compose start minio
```

## 数据迁移

### 从本地 Docker 迁移到 Supabase 云服务

1. **导出数据**：
   ```bash
   docker exec mxmai-postgres pg_dump -U postgres postgres > migration.sql
   ```

2. **在 Supabase Dashboard 中执行**：
   - 登录 Supabase Dashboard
   - 进入 SQL Editor
   - 执行 `migration.sql` 文件

3. **更新环境变量**：
   ```bash
   # 在 mxmdata/.env 中更新
   SUPABASE_URL=https://your-project.supabase.co
   SUPABASE_ANON_KEY=your-anon-key
   SUPABASE_SERVICE_KEY=your-service-key
   ```

### 从 Supabase 云服务迁移到本地 Docker

1. **在 Supabase Dashboard 中导出**：
   - 进入 Database → Backups
   - 下载备份文件

2. **或使用 Supabase CLI**：
   ```bash
   supabase db dump -f migration.sql
   ```

3. **导入到本地**：
   ```bash
   docker exec -i mxmai-postgres psql -U postgres postgres < migration.sql
   ```

## 数据清理

### 清理所有数据（⚠️ 危险操作）

```bash
cd mxmdata

# 停止所有服务
docker compose down

# 删除所有数据（⚠️ 不可恢复）
rm -rf data/postgres/*
rm -rf data/minio/*
rm -rf data/redis/*

# 重新启动服务（会重新初始化）
docker compose up -d
```

### 清理特定服务的数据

```bash
# 只清理 PostgreSQL 数据
docker compose stop postgres
rm -rf data/postgres/*
docker compose start postgres

# 只清理 MinIO 数据
docker compose stop minio
rm -rf data/minio/*
docker compose start minio
```

## 数据大小查看

### 查看各服务数据大小

```bash
cd mxmdata
du -sh data/*
```

### 查看 PostgreSQL 数据库大小

```sql
-- 在 Supabase SQL Editor 中执行
SELECT 
  pg_size_pretty(pg_database_size('postgres')) AS database_size;

-- 查看各表大小
SELECT 
  schemaname,
  tablename,
  pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) AS size
FROM pg_tables
WHERE schemaname = 'public'
ORDER BY pg_total_relation_size(schemaname||'.'||tablename) DESC;
```

## 重要提示

1. **数据目录已加入 .gitignore**：`mxmdata/data/` 目录不会被提交到 Git
2. **定期备份**：建议定期备份重要数据
3. **生产环境**：生产环境建议使用 Supabase 云服务，自动备份和恢复
4. **数据安全**：`data/` 目录包含敏感数据，不要分享或上传到公共仓库
