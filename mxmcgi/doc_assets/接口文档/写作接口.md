# 写作 API 完整接口文档

## 概述

写作模块提供文章生成、改写、润色等功能，支持流式输出（SSE）和异步任务两种模式。

## 路由映射规则

Gateway 配置：
- **Gateway 路径**：`/api/v1/writing/*`
- **目标服务**：`mxmcgi` (http://localhost:4003)
- **目标路径**：`/writing/*`
- **路径重写**：`/api/v1/writing` → `/writing`

## 基础信息

- **Base URL**: `http://localhost:3000/api/v1/writing`
- **认证方式**: Bearer Token（JWT）
- **Content-Type**: `application/json`

## 通用 Headers

```http
Authorization: Bearer <your-jwt-token>
Content-Type: application/json
```

Gateway 会自动添加以下 headers：
- `x-user-id`: 从 JWT token 中提取的用户 ID
- `x-username`: 从 JWT token 中提取的用户名

## 接口列表

### 1. 生成大纲

生成写作大纲，支持知识库增强。

**接口信息**
- **方法**: `POST`
- **路径**: `/api/v1/writing/outline`
- **模式**: 异步任务（不支持流式输出）

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| uid | string | 是 | 大纲根节点的唯一标识 |
| prompt | string | 是 | 写作要求/主题描述 |
| maxDepth | number | 否 | 大纲层级深度（默认 3） |
| expectedNodes | number | 否 | 期望节点总数（可选） |
| knowledgeBase | array | 否 | 知识库配置数组 |

**knowledgeBase 数组项结构**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| knowledgeBaseId | string | 是 | 知识库 ID |
| query | string | 是 | 搜索问题 |
| limit | number | 否 | 返回的相关文档数量（默认 5） |

**请求示例**

```bash
curl -X POST http://localhost:3000/api/v1/writing/outline \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "uid": "outline_001",
    "prompt": "写一篇关于人工智能发展的技术文章",
    "maxDepth": 3,
    "expectedNodes": 10,
    "knowledgeBase": [
      {
        "knowledgeBaseId": "kb_abc123",
        "query": "人工智能的发展历史",
        "limit": 5
      }
    ]
  }'
```

**响应示例**

```json
{
  "success": true,
  "data": {
    "taskId": "task_xxx",
    "status": "pending"
  }
}
```

**任务结果查询**

通过 `GET /api/v1/cgi-tasks/:taskId` 查询任务状态和结果。

**结果格式**

```json
{
  "success": true,
  "data": {
    "id": "task_xxx",
    "type": "other",
    "status": "completed",
    "result": {
      "metadata": {
        "type": "outline",
        "uid": "outline_001",
        "outline": {
          "uid": "outline_001",
          "content": "人工智能发展概述",
          "children": [
            {
              "uid": "sub_1",
              "content": "人工智能的起源",
              "children": [...]
            }
          ]
        }
      }
    }
  }
}
```

### 2. 生成文章

根据大纲或提示词生成文章，支持流式输出和异步任务两种模式。

**重要说明：有大纲和没有大纲使用不同的生成方案**

- **无大纲模式**：单次调用 LLM，一次性生成整篇文章
- **有大纲模式**：多次调用 LLM，根据大纲配置分段生成
  - **并行模式**（`generation_mode: 'parallel'`，默认）：先生成公用总结（500字内），然后并行生成各段落（速度快，适合段落较多的情况）
  - **流水形模式**（`generation_mode: 'sequential'`）：按顺序逐段生成，每段基于前文记忆（上下文连贯，适合段落较少的情况）
  - **自动模式**（`generation_mode: 'auto'`）：大纲节点 < 5 个用 sequential，>= 5 个用 parallel

**接口信息**
- **方法**: `POST`
- **路径**: `/api/v1/writing/generate`
- **模式**: 流式输出（SSE）或异步任务

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| prompt | string | 是 | 写作要求/提示词 |
| outlines | array | 否 | 大纲数组（如果提供，系统会根据大纲生成）<br/>**重要**：提供大纲时，系统会使用多段生成模式（并行或流水形），每个段落根据大纲配置独立生成 |
| previous_content | string | 否 | 之前的文本内容（用于续写） |
| previous_task | string | 否 | 之前的任务 ID（用于续写） |
| storage_form | string | 否 | 存储格式：`markdown`、`txt`、`pdf`（默认 `markdown`） |
| storeToMinio | boolean | 否 | 是否存储到 MinIO（默认 `true`） |
| outputFormat | string | 否 | 输出格式：`stream`（流式）或 `json`（异步任务，默认） |
| generation_mode | string | 否 | 生成模式（仅在有 `outlines` 时生效，默认 `parallel`）<br/>- `parallel`: 并行模式，先生成公用总结，然后并行生成各段落<br/>- `sequential`: 流水形模式，按顺序递归生成，每段基于前文记忆<br/>- `auto`: 自动选择，大纲节点 < 5 个用 sequential，>= 5 个用 parallel |
| enable_markdown | boolean | 否 | 是否启用 Markdown 格式输出（默认 `true`）<br/>- `true`: 输出标准 Markdown 格式（包括标题、列表、引用、表格等）<br/>- `false`: 输出纯文本格式（只有空格和换行，不使用 Markdown 语法） |
| metadata | object | 否 | 文档元数据（如 title、author、tags 等） |
| knowledgeBase | array | 否 | 知识库配置数组（全局配置，如果大纲节点没有配置则使用全局配置） |
| process_style | string | 否 | 知识库处理模式（默认 `silent`）<br/>- `silent`: 静默模式，知识库无召回时静默处理，继续生成<br/>- `strict`: 严格模式，知识库无召回时不调用大模型，返回错误"没有相关的知识内容"<br/>- `explain`: 解释模式，知识库无召回时仍调用大模型，但输出必须以"我们没有相关的专业知识，但是根据我的了解"开头 |

**knowledgeBase 数组项结构**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| knowledgeBaseId | string | 是 | 知识库 ID |
| query | string | 是 | 搜索问题 |
| limit | number | 否 | 返回的相关文档数量（默认 5） |
| relate_outline | string | 否 | 关联的大纲节点 UID |

**outlines 大纲数组结构**

每个大纲节点（Outline）的结构如下：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| uid | string | 是 | 段落唯一标识 |
| content | string | 是 | 段落标题/内容 |
| motivation | string | 否 | 写作动机（用于指导内容生成，不会直接输出） |
| stance | string | 否 | 立场（用于指导内容生成，不会直接输出） |
| tone | string | 否 | 语调（用于指导内容生成，不会直接输出） |
| length | string | 否 | 长度要求（如 "300-400字"） |
| key_elements | array | 否 | 关键要素数组（用于指导内容生成，不会直接输出） |
| children | array | 否 | 子节点数组（嵌套结构） |
| knowledgeBase | array | 否 | 该段落关联的知识库配置（优先于全局配置） |

**重要说明**：
- 如果大纲节点没有配置 `motivation`、`stance`、`tone`、`length`、`key_elements`，则只生成标题，无实际内容
- 每个段落根据自己对应的大纲配置独立生成
- 大纲节点可以有自己的 `knowledgeBase` 配置，如果未配置则使用全局 `knowledgeBase` 配置
- 系统会递归展开所有大纲节点（包括有 `children` 的节点），每个节点都会生成对应的段落

**流式输出模式** (`outputFormat: 'stream'`)

**请求示例**

```bash
curl -X POST http://localhost:3000/api/v1/writing/generate \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "根据大纲完成文章写作",
    "outlines": [
      {
        "uid": "intro_001",
        "content": "开场白：人工智能的魅力",
        "motivation": "吸引观众注意力",
        "tone": "热情、亲切",
        "length": "30秒，约150字",
        "key_elements": ["自我介绍", "AI的重要性"],
        "knowledgeBase": [
          {
            "knowledgeBaseId": "kb_abc123",
            "query": "人工智能的普及性",
            "limit": 3
          }
        ]
      },
      {
        "uid": "section_001",
        "content": "第一部分：AI技术基础",
        "children": [
          {
            "uid": "sub_001_01",
            "content": "机器学习基础",
            "stance": "推荐深度学习",
            "key_elements": ["监督学习", "神经网络"]
          }
        ]
      }
    ],
    "outputFormat": "stream",
    "generation_mode": "parallel",
    "enable_markdown": true,
    "knowledgeBase": [
      {
        "knowledgeBaseId": "kb_abc123",
        "query": "人工智能的核心技术",
        "limit": 5
      }
    ]
  }'
```

**响应格式（SSE）**

**无大纲模式**（单次生成）：
```
data: {"chunk":"生成的文本片段","status":"streaming","collection":"累积文本"}

data: {"chunk":"...","status":"streaming","collection":"..."}

data: {"chunk":"","status":"completed","collection":"完整文本"}

data: [DONE]
```

**有大纲模式**（多段生成，并行或流水形）：
每个 chunk 包含段落位置信息（`section` 字段），用于标识该内容属于哪个段落：

```
data: {"chunk":"段落内容...","status":"streaming","collection":"","section":{"uid":"intro_001","index":0,"position":0}}

data: {"chunk":"...","status":"streaming","collection":"","section":{"uid":"intro_001","index":0,"position":0}}

data: {"chunk":"","status":"completed","collection":"","section":{"uid":"intro_001","index":0,"position":0}}

data: {"chunk":"段落内容...","status":"streaming","collection":"","section":{"uid":"section_001","index":1,"position":1}}

...

data: [DONE]
```

**段落位置信息说明**：
- `section.uid`: 段落在大纲中的唯一标识（对应 `outlines` 中的 `uid`）
- `section.index`: 段落在大纲中的顺序索引（从 0 开始）
- `section.position`: 在最终文章中的位置（用于前端排序，从 0 开始）

**并行模式特点**：
- 先输出公用总结（`uid: "summary"`, `index: -1`, `position: 0`）
- 然后并行生成各段落，实时输出
- 多个段落可能同时生成，chunks 可能乱序到达，需根据 `section.position` 排序

**流水形模式特点**：
- 按顺序逐段生成
- 每个段落完成后才开始下一个
- chunks 按顺序到达，`section.position` 递增

**异步任务模式** (`outputFormat: 'json'` 或默认)

**enable_markdown 参数说明**

- **`enable_markdown: true`**（默认）：输出标准 Markdown 格式
  - 使用 `#`、`##`、`###` 等表示标题
  - 支持列表（`-`、`1.`）、引用（`>`）、表格（`|`）、代码块（```）等 Markdown 语法
  - 适合需要格式化展示的场景

- **`enable_markdown: false`**：输出纯文本格式
  - 不使用任何 Markdown 语法
  - 只使用空格和换行符进行格式化
  - 标题使用空行分隔，不使用 `#` 等符号
  - 适合需要纯文本输出的场景（如某些文本处理、导入其他系统等）

**请求示例**

```bash
curl -X POST http://localhost:3000/api/v1/writing/generate \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "写一篇关于人工智能的文章",
    "outputFormat": "json",
    "storage_form": "markdown",
    "storeToMinio": true,
    "enable_markdown": true,
    "metadata": {
      "title": "AI 技术发展",
      "author": "用户A",
      "tags": ["AI", "技术"]
    },
    "knowledgeBase": [
      {
        "knowledgeBaseId": "kb_abc123",
        "query": "人工智能的发展历史",
        "limit": 5
      }
    ]
  }'
```

**响应示例**

```json
{
  "success": true,
  "data": {
    "taskId": "task_xxx",
    "status": "pending"
  }
}
```

**任务结果查询**

通过 `GET /api/v1/cgi-tasks/:taskId` 查询任务状态和结果。

**结果格式**

```json
{
  "success": true,
  "data": {
    "id": "task_xxx",
```

### 5. 动机、立场、语调参数使用案例

写作接口支持通过 `motivation`（动机）、`stance`（立场）、`tone`（语调）三个参数来控制文章的写作风格和内容导向。这些参数可以在以下场景中使用：

1. **润色接口** (`/api/v1/writing/polishing`)：直接作为请求参数传递
2. **生成接口** (`/api/v1/writing/generate`)：通过 `outlines` 数组中的每个节点传递

#### 参数说明

| 参数 | 类型 | 说明 | 使用场景 |
|------|------|------|----------|
| motivation | string | 写作动机，解释为什么写这个内容 | 帮助 AI 理解写作目的，影响内容深度和角度 |
| stance | string | 立场，文章的观点倾向 | 控制文章的观点偏向（如：支持、反对、中立、批判等） |
| tone | string | 语调，文章的语言风格 | 控制文章的语气（如：专业、轻松、严肃、幽默等） |

**案例 1：技术分享文章（专业、客观）**

### 6. 同步 Stream 文本到任务系统

将 stream 模式下生成的文本同步到任务系统，方便后续通过任务接口追踪。

**使用场景**：
- 用户使用 `outputFormat: 'stream'` 接收实时文本流
- 接收完成后，需要将文本保存为任务以便后续追踪
- 系统会创建任务、格式化文档、存储到 MinIO，并立即标记为完成

**接口信息**
- **方法**: `POST`
- **路径**: `/api/v1/writing/sync-to-task`

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| text | string | 是 | 从 stream 接收并拼接的完整文本内容 |
| storage_form | string | 否 | 文件格式：`markdown`、`txt`、`pdf`（默认 `markdown`） |
| storeToMinio | boolean | 否 | 是否存储到 MinIO（默认 `true`） |
| metadata | object | 否 | 文档元数据（如 title、author、tags 等） |

**请求示例**

```bash
curl -X POST http://localhost:3000/api/v1/writing/sync-to-task \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "# 标题\n\n这是从 stream 接收并拼接的完整文本内容...",
    "storage_form": "markdown",
    "storeToMinio": true,
    "metadata": {
      "title": "AI 技术发展",
      "author": "用户A",
      "tags": ["AI", "技术"]
    }
  }'
```

**响应示例**

```json
{
  "success": true,
  "data": {
    "taskId": "task_xxx",
    "storageInfo": {
      "key": "user-123/writing/1234567890-abc123.md",
      "bucket": "user-media",
      "url": "http://localhost:9000/user-media/..."
    },
    "metadata": {
      "wordCount": 1500,
      "fileSize": 4500,
      "format": "markdown",
      "title": "AI 技术发展",
      "author": "用户A",
      "tags": ["AI", "技术"]
    },
    "message": "文本已成功同步到任务系统"
  }
}
```

**说明**：
- 任务类型为 `writing`
- 任务状态立即设置为 `completed`
- 可以通过 `GET /api/v1/cgi-tasks/:taskId` 查询任务详情
- 文档会自动存储到 MinIO，并生成预签名 URL

### 6. 读取文档

从 MinIO 读取已存储的文档。

**接口信息**
- **方法**: `GET`
- **路径**: `/api/v1/writing/document`

**查询参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| bucket | string | 是 | MinIO 存储桶名称 |
| key | string | 是 | 文件键（路径） |

**请求示例**

```bash
curl -X GET "http://localhost:3000/api/v1/writing/document?bucket=user-media&key=user-123/writing/1234567890-abc123.md" \
  -H "Authorization: Bearer <token>"
```

**响应示例**

```json
{
  "success": true,
  "data": {
    "content": "# 文档内容\n\n这是从 MinIO 读取的文档...",
    "format": "markdown",
    "metadata": {
      "contentType": "text/markdown",
      "size": 1234,
      "lastModified": "2024-01-01T00:00:00Z"
    }
  }
}
```

## 模型选择

系统会根据任务类型自动选择最适合的模型：

- **大纲生成** (`outline`): `claude-4.5-sonnet`、`gemini-3-pro`（逻辑性强）
- **段落写作** (`paragraph`): `gpt-5-nano`、`gemini-2-5-flash`（流畅性强）
- **完整文章** (`full`): `claude-4.5-sonnet`、`gemini-3-pro`（综合能力强）

用户无需指定模型，系统会自动选择。

## 知识库集成

所有写作接口都支持知识库集成：

1. 提供 `knowledgeBase` 数组参数
2. 系统自动从知识库检索相关内容
3. 将检索结果作为上下文增强 prompt
4. 支持多个知识库同时使用

**示例**

```json
{
  "prompt": "写一篇关于机器学习的技术文章",
  "knowledgeBase": [
    {
      "knowledgeBaseId": "kb_ml_basics",
      "query": "机器学习的基本概念",
      "limit": 5
    },
    {
      "knowledgeBaseId": "kb_ml_applications",
      "query": "机器学习的实际应用",
      "limit": 3,
      "relate_outline": "sub_2"  // 关联到特定大纲节点
    }
  ]
}
```

## 注意事项

1. **流式输出**：使用 `outputFormat: 'stream'` 时，响应为 SSE 格式，需要客户端支持 SSE 解析
2. **异步任务**：使用 `outputFormat: 'json'` 或默认时，需要通过 `GET /api/v1/cgi-tasks/:taskId` 查询结果
3. **文档存储**：默认存储到 MinIO，可通过 `storeToMinio: false` 禁用
4. **权限控制**：只能访问自己创建的任务和文档
5. **知识库权限**：只能使用自己有权限访问的知识库
