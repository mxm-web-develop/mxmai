# 全流程测试：大纲 → 分镜脚本（带角色）→ 视频生成

本文档描述从**大纲生成**到**分镜脚本写作**（含人物角色），再到**用写作结果生成视频**的完整 API 测试流程。  
与《视频生成请求示例-带参考图.md》的区别：后者仅覆盖「视频生成」单接口；本文档覆盖三步串联。

---

## 前置说明

- **Base URL**：经 Gateway 代理时使用 `http://localhost:3000`（或你的 Gateway 地址）。
- **认证**：所有请求需带 `Authorization: Bearer <JWT>`；Gateway 会解析并转发 `x-user-id`。
- **角色来源**：分镜中的「人物」可来自角色库。若尚未创建角色，可先调用角色接口创建并拿到 `id`，再在大纲/写作中传入 `cast_character_ids` / `metadata.character_ids`。

---

## 流程总览

| 步骤 | 说明 | 产出 |
|------|------|------|
| 0（可选） | 创建/查询角色 | 角色 `id`，用于后续大纲与写作 |
| 1 | 生成大纲 | `outlineTaskId` → 轮询得到 `result.metadata.outline` |
| 2 | 分镜脚本写作 | `writingTaskId` → 轮询得到 `result.metadata`（含 chunks、characters） |
| 3 | 用写作结果生成视频 | 用步骤 2 的 chunks + 按角色名填 `reference_image_url`，调用视频生成 |

---

## 步骤 0（可选）：准备角色

若分镜中需要「有人物设定」的角色，可先在角色库中创建，或使用已有角色。**用于视频成片时，角色必须带有参考图**：系统会取 `appearance.reference_images` 或 `clothing_style.reference_images` 的首张 URL 作为该角色的 `reference_image_url`，供分镜成片时作形象参考。

**角色创建参数说明**（与 `CreateCharacterDto` 对齐，`user_id` 由服务端从 JWT 注入，无需传）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 角色名 |
| `nickname` | string | 否 | 昵称 |
| `age` | number | 否 | 年龄 |
| `category` | string[] | 否 | 分类 |
| `tags` | string[] | 否 | 标签 |
| `appearance` | object | 否 | 外表 |
| `appearance.description` | string | 否 | 外表文字描述 |
| `appearance.reference_images` | string[] | 否 | **参考图 URL 数组，最多 10 张**；视频成片时优先取首张作形象参考 |
| `clothing_style` | object | 否 | 服装风格 |
| `clothing_style.description` | string | 否 | 服装风格文字描述 |
| `clothing_style.reference_images` | string[] | 否 | **参考图 URL 数组，最多 10 张**；若无 appearance 参考图则取此处首张 |
| `voice` | object | 否 | 声音（description / clone_voiceId / voice_example） |
| `reference_videos` | string[] | 否 | 参考视频 URL |
| `others` | object | 否 | 其他（如 personality 等） |
| `relations` | object | 否 | 与其他角色的关系 |

**创建角色**（示例，含参考图）：

```bash
curl -X POST 'http://localhost:3000/api/v1/cgi/characters' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_JWT_TOKEN' \
  -d '{
    "name": "喵小游",
    "nickname": "小游",
    "appearance": {
      "description": "年轻女性，短发，休闲装",
      "reference_images": ["https://your-cdn.com/avatar-miaoxiaoyou.jpg"]
    },
    "clothing_style": {
      "description": "户外运动风，常背小包",
      "reference_images": []
    },
    "others": {
      "personality": "开朗、喜欢徒步"
    }
  }'
```

- 至少在一处提供参考图：`appearance.reference_images` 或 `clothing_style.reference_images`（非空数组，首张将作为该角色的 `reference_image_url`）。
- 响应中会返回角色 `id`，记作 `CHARACTER_ID`，用于步骤 1、2。

**列出角色**（获取已有角色 id）：

```bash
curl -X GET 'http://localhost:3000/api/v1/cgi/characters' \
  -H 'Authorization: Bearer YOUR_JWT_TOKEN'
```

## 步骤 1：生成大纲

- **接口**：`POST /api/v1/cgi/writing/outline`（经 Gateway 代理到 mxmcgi 的 `/writing/outline`）
- **作用**：生成分镜用大纲；可选传入 `cast_character_ids` 以引入角色，便于后续写作与视频参考图绑定。

**请求示例**：

```bash
curl -X POST 'http://localhost:3000/api/v1/cgi/writing/outline' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_JWT_TOKEN' \
  -d '{
    "uid": "outline-'$(date +%s)'",
    "prompt": "一支 30 秒的短视频：主角在山间徒步，从清晨出发到登顶看日出，节奏舒缓、画面唯美。",
    "applyto": "storyboard-scripts",
    "outline_type": "short-video-storyboard",
    "outline_structure_type": "act-scene-storyboard",
    "total_duration_seconds": 30,
    "cast_character_ids": ["CHARACTER_ID"],
    "language": "zh"
  }'
```

将 `CHARACTER_ID` 替换为上一步得到的角色 id（若无角色可省略 `cast_character_ids`）。

**响应示例**：

```json
{
  "success": true,
  "data": {
    "taskId": "outline-task-xxx",
    "status": "pending"
  }
}
```

**轮询大纲任务**：直到 `status === 'completed'`，再取 `result.metadata.outline`（及若有 `result.metadata.characters` 也可保留，写作阶段可沿用）。

```bash
curl -X GET 'http://localhost:3000/api/v1/cgi-tasks/outline-task-xxx' \
  -H 'Authorization: Bearer YOUR_JWT_TOKEN'
```

响应中的 `data.result.metadata.outline` 为大纲树（含 `uid`、`content`、`cast` 等）；`data.result.metadata.characters` 可能包含大纲阶段解析出的角色信息。

---

## 步骤 2：分镜脚本写作（带人物角色）

- **接口**：`POST /api/v1/cgi/writing/generate`
- **作用**：用步骤 1 的大纲 + 角色生成分镜脚本（JSON chunks），并可在结果中带出角色信息，供步骤 3 填 `reference_image_url`。

**请求示例**：

```bash
curl -X POST 'http://localhost:3000/api/v1/cgi/writing/generate' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_JWT_TOKEN' \
  -d '{
    "prompt": "根据大纲生成分镜脚本，注意每镜标注出场角色。",
    "writing_type": "storyboard-scripts",
    "outline_type": "short-video-storyboard",
    "outlines": [OUTLINE_JSON],
    "storyboard_chunk_seconds": 10,
    "metadata": {
      "character_ids": ["CHARACTER_ID"]
    },
    "language": "zh",
    "storeToMinio": true
  }'
```

将 `OUTLINE_JSON` 替换为步骤 1 中 `result.metadata.outline` 的完整 JSON（通常是一个数组，即大纲节点数组；若后端接受单个根节点则按实际接口要求传）。  
将 `CHARACTER_ID` 替换为实际角色 id。

**响应示例**：

```json
{
  "success": true,
  "data": {
    "taskId": "writing-task-xxx",
    "status": "pending",
    "createdAt": "2025-02-07T12:00:00.000Z"
  }
}
```

**轮询写作任务**：

```bash
curl -X GET 'http://localhost:3000/api/v1/cgi-tasks/writing-task-xxx' \
  -H 'Authorization: Bearer YOUR_JWT_TOKEN'
```

当 `data.status === 'completed'` 时：

- **分镜 chunks**：来自 `data.result.metadata.text` 或 `data.result.metadata.formattedContent`。  
  - 若为 `formattedContent` 且为 base64，需先解码再解析 JSON。  
  - 内容通常为 `{ "chunks": [ ... ] }` 或直接为 `[ ... ]` 数组，每项含 `prompt`、`chunk_seconds`、`characters_in_shot` 等。
- **角色列表（用于填参考图）**：来自 `data.result.metadata.characters`。  
  - 若仅有 `data.result.metadata.character_ids`，当前实现会在 GET 任务时由服务端解析为 `characters`（含 `name`、`id`、`reference_image_url` 等）。  
  - 用「角色名 → reference_image_url」做映射，在步骤 3 里为每个 chunk 的 `characters_in_shot` 填上 `reference_image_url`。

---

## 步骤 3：用写作结果生成视频

- **接口**：`POST /api/v1/cgi/video/generate`（与《视频生成请求示例-带参考图.md》一致）
- **要点**：  
  - 使用步骤 2 解析出的 **chunks** 作为请求体中的 `chunks`。  
  - 每个 chunk 若有 `characters_in_shot`，则根据步骤 2 的 `result.metadata.characters`，按**角色名**找到对应 `reference_image_url` 填入该 chunk 的 `reference_image_url`（或 `input_reference`），这样视频生成会带人物参考图。

**手动从写作结果拼装请求体**（API 测试时常用）：

1. 从步骤 2 的 GET 任务响应中取出 `result.metadata.text` 或解码 `result.metadata.formattedContent`，得到分镜 JSON。
2. 取出 `chunks` 数组；若根结构是 `{ chunks: [...] }` 则用 `chunks` 字段。
3. 从 `result.metadata.characters` 构建「角色名 → reference_image_url」映射。
4. 遍历每个 chunk：若 `characters_in_shot` 非空，用第一个（或约定规则）在映射中的角色对应的 `reference_image_url` 填入该 chunk 的 `reference_image_url`。
5. 调用视频生成接口，body 中传 `chunks`、`scriptType`、`label`、`orientation`、`storeToMinio` 等。

**请求示例**（chunks 已按上面规则填好 `reference_image_url`）：

```bash
curl -X POST 'http://localhost:3000/api/v1/cgi/video/generate' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_JWT_TOKEN' \
  -d '{
    "chunks": [
      {
        "index": 1,
        "chunk_seconds": 10,
        "prompt": "清晨山谷，薄雾缭绕。喵小游背着小包沿山路缓行，远处溪水与鸟鸣。",
        "video_description": "清晨山谷，薄雾缭绕。喵小游背着小包沿山路缓行。",
        "characters_in_shot": ["喵小游"],
        "reference_image_url": "https://your-cdn.com/avatar-miaoxiaoyou.jpg"
      },
      {
        "index": 2,
        "chunk_seconds": 10,
        "prompt": "镜头切至山腰远景，喵小游继续向上攀登，阳光从云隙洒下。",
        "video_description": "山腰远景，喵小游继续攀登，阳光从云隙洒下。",
        "characters_in_shot": ["喵小游"],
        "reference_image_url": "https://your-cdn.com/avatar-miaoxiaoyou.jpg"
      }
    ],
    "scriptType": "short-video-storyboard",
    "label": "全流程测试-分镜成片",
    "orientation": "landscape",
    "storeToMinio": true
  }'
```

其中的 `reference_image_url` 在实际测试中应替换为步骤 2 中 `result.metadata.characters` 里该角色对应的 `reference_image_url`（通常来自角色库中该角色的形象图）。

**说明**：

- 在 **App 内**：写作详情页跳转「去生成视频」时会带上 `writingTaskId`；视频创建页会拉取该写作任务，根据 `metadata.characters` 与各 chunk 的 `characters_in_shot` 自动为每个 chunk 填 `reference_image_url`，无需手拼。
- 在 **纯 API/脚本测试**中：没有 `writingTaskId` 参数，需按上文「手动拼装」方式从 GET 写作任务结果中取 chunks 和 characters，自行填好 `reference_image_url` 再调用视频生成。

## 字段速查

| 步骤 | 关键字段 | 说明 |
|------|----------|------|
| 大纲 | `applyto` | `"storyboard-scripts"` 表示大纲用于分镜 |
| 大纲 | `outline_type` | 如 `"short-video-storyboard"` |
| 大纲 | `cast_character_ids` | 角色 id 数组，可选 |
| 写作 | `writing_type` | `"storyboard-scripts"` |
| 写作 | `outlines` | 步骤 1 的 `result.metadata.outline` |
| 写作 | `metadata.character_ids` | 角色 id 数组，结果中会带出/解析为 `characters` |
| 写作结果 | `result.metadata.characters` | 含 `name`、`id`、`reference_image_url` 等 |
| 写作结果 | `result.metadata.text` / `formattedContent` | 分镜 JSON（chunks） |
| 视频 | `chunks[].characters_in_shot` | 该镜出场角色名数组 |
| 视频 | `chunks[].reference_image_url` | 该镜参考图（由角色名从 characters 映射得到） |

---

## 一键脚本思路（伪代码）

便于本地或 CI 做全流程自动化测试：

1. 可选：POST 创建角色，记下 `id`。
2. POST 大纲，拿到 `outlineTaskId`；循环 GET 该任务直到 `status === 'completed'`，取出 `result.metadata.outline`。
3. POST 写作 generate，body 中带 `outlines` 与 `metadata.character_ids`，拿到 `writingTaskId`；循环 GET 该任务直到完成，取出 `result.metadata.text`/`formattedContent` 得到 chunks，以及 `result.metadata.characters`。
4. 遍历 chunks，按 `characters_in_shot` 与 `characters` 填好每个 chunk 的 `reference_image_url`。
5. POST 视频 generate，body 为 `{ chunks, scriptType, label, orientation, storeToMinio }`。

可将上述步骤写成 shell 或 Node 脚本，用环境变量传入 `BASE_URL`、`JWT`、可选 `CHARACTER_ID`，便于在不同环境复现。
