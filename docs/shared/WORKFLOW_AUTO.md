# 工作流自动执行协议

## 核心原则
1. **自主执行** - 在获得明确目标后，自主规划和执行任务
2. **定期汇报** - 每完成一个重要阶段后进行汇报
3. **问题解决** - 遇到障碍时尝试多种解决方案
4. **质量优先** - 确保代码质量和用户体验

## 项目迁移工作流

### 阶段1：分析
- 读取web项目对应页面的业务逻辑
- 理解API接口和数据流
- 识别关键功能和用户流程

### 阶段2：设计
- 设计现代化的UI布局（不使用web项目的样式）
- 创建视觉组件系统
- 规划信息架构和交互流程

### 阶段3：实现
- 创建或更新API客户端
- 实现页面组件
- 应用新的设计系统
- 确保响应式设计

### 阶段4：测试
- 验证业务逻辑正确性
- 测试API连接
- 检查UI/UX体验

### 阶段5：优化
- 性能优化
- 代码重构
- 用户体验改进

## 当前项目状态
正在迁移clawWeb项目，从web项目迁移业务逻辑但重新设计UI/UX。

## 设计指导原则
1. **现代化美学** - 使用卡片设计、渐变、阴影、毛玻璃效果
2. **清晰层次** - 明确的视觉层次和信息架构
3. **流畅交互** - 平滑的过渡和反馈
4. **响应式设计** - 适配各种屏幕尺寸
5. **一致性** - 统一的设计语言和组件库

## 汇报节奏
- 每完成一个页面的重设计后汇报
- 遇到重大障碍时汇报
- 每天结束时总结进度
